### Jobflow: AI pipelines for recruiting

Jobflow is a recruiting platform. I work on the AI side: the pipelines that read recruiter and candidate conversations and turn them into actions on the platform. Most of this is in one large monorepo, so I describe the work at the level of what it does, not how the company's systems are named.

## Interview confirmation and task extraction

The interview analyzer reads a conversation and decides whether an interview was confirmed, moved or missed. When it is confirmed, the platform creates the interview, updates the calendar and sends the notifications. I refactored the analyzer into a pure workflow step and built OCR evals for interview PDFs. I also built the no-show detector and later hardened it with scheduling validation.

The task extractor turns recruiter messages into structured tasks with reminders, and marks a task finished when a later message resolves it. It was built eval first: the PR that introduced the full task shape also introduced the scoring for it.

Both pipelines were rolled out behind a feature flag. After the rollout I deleted the retired v1 to v3 code, about 16,000 lines, so there is one pipeline to maintain.

## Evals and tracing

The AI services have fixture datasets and run in Braintrust. I set up the project layout, the shared sampling, nested trace spans so one conversation reads as one tree, and an end-to-end chain eval scored by an LLM judge. The same evals were used to decide a model change: non-sensitive prompts moved to a cheaper model after the evals.

I also wrote the prompts and eval datasets for scraping and importing job data, using realistic page noise, and extended the extraction for scraped companies.

## Search that stopped being slow

The admin tool that estimates how many users and teams are within a distance of a job location was slow. I measured it with a benchmark script on a near-production clone, then replaced the per-row distance calculation with a PostGIS geography column and a partial GIST index. On that data the estimate went from about 90 seconds to about 100 milliseconds. The change also added input validation for coordinates, smaller responses and integration tests.

## CV and cover letter rendering

CV and cover letter PDFs had a stretch of about ten rendering fixes in three months. I extended the smoke tests so every CV and cover letter template is rendered to a PDF. It checks that rendering works, not pixels. Afterwards only a handful of CV fixes were needed.
